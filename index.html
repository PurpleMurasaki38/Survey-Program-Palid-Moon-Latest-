## O loop fundamental (ReAct aplicado a pentest)

```
ALVO → RECON → PLANEJAR → EXECUTAR → OBSERVAR/PARSEAR → DECIDIR → (repete) → REPORT
```

1. **Normalização do alvo**: usuário passa domínio/IP/API. O agente extrai escopo (hosts, portas permitidas, tipo de alvo: web app, API REST, rede).
2. **Recon (camada 1)**: subdomain enum (`subfinder`, `amass`) → port scan (`nmap -sV --top-ports`) → fingerprint HTTP (`httpx`, `whatweb`). Isso roda via tool calling — o LLM não "adivinha", ele chama ferramentas.
3. **Parse estruturado**: a saída crua do nmap **não vai pro LLM como texto gigante**. Você converte pra JSON: `{host, porta, serviço, versão, banners}`. Isso é o que separa agente inteligente de agente burro — a janela de contexto explode se você jogar raw output.
4. **Planner decide a próxima ação**: com o estado atual (`achou API REST na porta 8000, FastAPI, docs abertas em /docs`), o LLM escolhe: fuzz de endpoints? testar auth JWT? IDOR? Ele escolhe a **ferramenta e os argumentos**, não executa nada direto.
5. **Executor determinístico**: uma camada de código (não LLM) que valida o comando, roda a ferramenta, controla timeout e captura saída. Aqui moram os guardrails de escopo.
6. **Razor de validação**: achar um `403` não é vulnerabilidade. O agente testa bypass (`X-Original-URL`, path traversal em rota), confirma, e só aí registra como finding com severidade.
7. **Loop com memória**: findings num store dedup, hipóteses testadas e resultados — pra não re-testar a mesma coisa.
8. **Report**: CVSS, evidência (request/response), remediação.
